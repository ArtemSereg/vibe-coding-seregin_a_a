## 1. Описание деплоя

### Какой способ выбрали
Для деплоя был выбран запуск бота на платформе **Railway** с использованием Python-проекта и установки зависимостей из `requirements.txt`.

### Почему именно этот
Этот способ был выбран потому что:
- Railway автоматически определяет Python-проект;
- не нужно вручную настраивать сервер;
- удобно хранить переменные окружения через `Variables`;
- бот может работать постоянно без запуска на локальном компьютере;
- сервис подходит для учебного проекта и не требует сложной инфраструктуры.

### URL бота
- Ссылка на Telegram-бота: **@itmoftmi_saa_bot**

## 2. Процесс деплоя

### Пошаговая инструкция
1. Подготовили проект к деплою.
2. Добавили зависимости в `requirements.txt`.
3. Проверили, что бот читает токен из переменной окружения `TELEGRAM_BOT_TOKEN`.
4. Загрузили проект в Railway.
5. Добавили переменную окружения `TELEGRAM_BOT_TOKEN` в `Variables`.
6. Запустили сервис и проверили логи.
7. Убедились, что бот стартует без ошибок и отвечает в Telegram.

### С какими проблемами столкнулись
Во время деплоя возникли следующие проблемы:
- сначала были ошибки из-за отсутствия токена в окружении;
- затем появилась несовместимость версии `python-telegram-bot` с Python 3.13;
- позже возник конфликт polling при запуске нескольких экземпляров бота.

### Как решили
Проблемы решили так:
- добавили переменную окружения `TELEGRAM_BOT_TOKEN` в Railway;
- обновили `python-telegram-bot` до версии, совместимой с окружением Railway;
- оставили запуск только одного экземпляра бота, чтобы не было конфликта `getUpdates`.
